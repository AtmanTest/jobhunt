3Le flux
Issue→ PO→ Spec Review→ Architecte→ QA→ Dev→ CI→ QA Review→ PR + rapport
Fix
Boucle de correction bornée échec CI → Fix (max 3 tentatives) → CI. Au-delà : arrêt et remontée du blocage, jamais de boucle infinie.

Chaque étape est un enchaînement de prompts avec vérification intermédiaire : aucune sortie ne passe sans preuve.

4Les quatre portes de qualité
PortePreuve exigéeÉchec
1. Spec Reviewverdict + bloquantsNO-GO : on ne code pas
2. Critères testablestable AC → CTAC non testable = réécrit
3. CIfingerprint_tested vs fingerprint_headrefused
4. QA Reviewverdict + preuve par testred → boucle Fix

Verdicts journalisés : green · red · refused. Un refus n'est pas un échec de test : c'est un refus de certifier.

6Ce que la chaîne applique d'ISTQB CT-GenAI
  • 6 composants de prompt — rôle, contexte, instruction, données, contraintes, format
  • Enchaînement de prompts — la chaîne entière, vérifiée à chaque étape
  • Few-shot — les cas existants servent d'exemples à l'agent QA
  • Méta-prompting — la Spec Review attaque la consigne
  • Hallucination — aucune sortie acceptée sans test qui tourne
  • Non-déterminisme — verdict sur faits reproductibles

Vie privée : les formulaires et les tests interdisent toute donnée personnelle · Shadow AI : un seul point d'entrée, tracé et versionné.
